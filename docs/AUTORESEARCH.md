# Autoresearch 进化自动化说明

本文定义本项目的进化式优化流程。目标是让“优化 3 轮”变成可重复执行、可评分、可回滚的工程流程，而不是一次临场发挥。

## 适应度函数

默认总分 100 分：

| 指标 | 权重 | 验证方式 |
| --- | ---: | --- |
| 构建与编译 | 30 | `scripts/eval.ps1` 中的前端 build、后端 compile/import 全部通过 |
| 核心流程稳定性 | 25 | 上传限制、任务状态、错误提示、临时文件清理不回退 |
| 手机端可用性 | 20 | API 地址可配置，局域网访问路径清晰，界面状态不会被旧任务覆盖 |
| 提示词质量 | 15 | 输出结构完整，失败时有可读错误，结果便于复制 |
| 文档与配置 | 10 | README、配置示例、设计文档与实际代码一致 |

若某项没有自动化验证，报告中必须标记为“人工验证”或“未验证”，不能写成已完成。

## 三轮默认进化目标

### 第 1 轮：生存性

重点保证工具能稳定跑完核心链路。

候选方向示例：

- 最小修复上传、轮询、错误提示和文件清理。
- 引入持久化任务队列。
- 改为同步长请求，移除轮询。

胜出标准：构建通过，真实使用风险最低，改动范围可控。

### 第 2 轮：质量

重点提高输出提示词和失败兜底质量。

候选方向示例：

- 强化模型 prompt 和 JSON 解析兜底。
- 增加结果重试与修复格式流程。
- 增加抽帧摘要后再合成提示词。

胜出标准：输出结构更稳定，失败信息更可读，不明显增加部署复杂度。

### 第 3 轮：形态

重点优化手机端和部署体验。

候选方向示例：

- 保持 Vite proxy + 可配置 API 基址。
- 改为 FastAPI 托管前端静态文件。
- 增加 Docker/一键启动脚本。

胜出标准：用户本机和手机访问路径最少出错，维护成本合理。

## 候选报告格式

每个候选必须记录到 `docs/evolution/`：

```markdown
# Round 1 Candidate A

## 假设

本候选想解决什么问题。

## 改动

列出关键文件和行为变化。

## 验证

粘贴 `scripts/eval.ps1` 的结果摘要。

## 评分

| 指标 | 得分 | 说明 |
| --- | ---: | --- |
| 构建与编译 | 30/30 | 通过 |
| 核心流程稳定性 | 20/25 | 仍缺少真实视频 E2E |

总分：80/100

## 淘汰或保留原因

说明为什么进入下一轮，或为什么淘汰。
```

## 自动化边界

脚本负责创建运行目录、执行验证、记录状态；Agent 负责提出候选和实现代码；适应度函数负责选择胜者。

没有 git 时，使用 `.evolution/runs/` 存放运行记录。有 git 时，推荐每个候选使用独立分支或 worktree。
